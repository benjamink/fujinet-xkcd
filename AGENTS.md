# AGENTS

xkcd viewer for the Amiga 500 (Kickstart 1.3+) that fetches comics through a
FujiNet running fujinet-nio firmware. Built with the
[MekkoGX](https://github.com/FozzTexx/MekkoGX) cross-platform template.

## Build and test

```sh
source "$NIO_WORKSPACE/scripts/env.sh"   # amiga-gcc on PATH, FUJINET_NIO_LIB, etc.
make test     # host gcc unit tests of the portable code in src/ (fast; run every change)
make amiga    # r2r/amiga/xkcd and r2r/amiga/xkcd.adf; must build with 0 warnings
```

`make amiga` asks `fujinet-nio-lib`'s own build to refresh
`build/fujinet-nio-amiga.a`. The workspace `env.sh` exports `FUJINET_LIB` (the
6502 library); the top-level Makefile forces it undefined on purpose. Don't
remove that override.

## Layout and MekkoGX rules

- `src/` holds portable C99 with no Amiga headers: JSON, xkcd model, history,
  wrap, selector, ILBM decoder, netmap, jsonstrip and autorange. It is built for
  the Amiga **and** compiled by `tests/Makefile.host` with `-Werror`. Put any
  logic that can be tested on the host here, with a test in `tests/test_main.c`.
- `src/amiga/` holds Intuition/Exec code (ui, dialogs, zoom, net, timer, rng,
  main). It is only built for `amiga`.
- Project-specific settings live **only** in the top-level `Makefile`. Files
  under `mekkogx/` are the shared template:
  - Don't customise them.
  - `platforms/amiga.mk` and `toolchains/amigagcc.mk` are this repo's own
    additions to the template, not upstream MekkoGX files. Keep them generic,
    in the same style as the other platform and toolchain files, and put
    project-specific settings in the top-level `Makefile` instead.
- Disk contents come from `DISK_EXTRA_FILES_AMIGA` entries in `src:dest` form.
  Icons are generated by `tools/mkinfo.py` from `amiga/gfx/*.icon.txt`, and the
  generated `.info` files are committed, so the build never needs Python.

## Amiga constraints (non-negotiable)

- **Kickstart 1.3 / V33 only.** Use raw Intuition structs. Do not use GadTools,
  ASL, tag-based calls or `CreateMsgPort`. Use `CreatePort`/`CreateExtIO` from
  amiga.lib. Do not rely on return values that only exist from V36, for example
  `SetMenuStrip`.
- `-mcrt=nix13`, 68000 and **no floating point**.
- A500 with 512 KB chip RAM is the minimum:
  - Check every chip allocation. On failure, show a message and never crash.
  - Zoom needs about 80 KB of chip RAM for the screen (2 bitplanes; the
    pre-check wants about 96 KB free on PAL) and refuses
    gracefully without it.
  - Zoom keeps the compressed ILBM in `MEMF_ANY` memory (at most 256 KB) and
    decodes only the visible rows into the screen; it never decodes the whole
    image.
- Never `WaitIO` an IORequest that was only opened and never sent.
- Free every resource on every exit path:
  - `ClearMenuStrip` before `CloseWindow`;
  - `CloseWindow` before `CloseScreen`;
  - `ReplyMsg` every IntuiMessage, and never touch it afterwards;
  - remove the Fetch ID input.device handler before freeing anything it uses.
- The ILBM decoder writes straight into screen bitplanes. Image placement must
  stay word-aligned and inside the box, via `ui_place_image()` (main view).
  Zoom places its own image: word-aligned x, clamped to the bitmap row width.

## FujiNet contract

- Images come from the firmware's content translation type **Image (4)** via
  `fn_open_translated()`. The selector string (`src/selector.c`) is the
  contract with the firmware's `parse_selector`, and it must match character for
  character. The grammar is in `fujinet-nio/docs/network_device_protocol.md`.
  This app sends `fmt=ilbm,bits=4` prefix, plus spatial and palette keys.
  If you change a selector, re-check it against that grammar.
  The Zoom selector is exactly
  `fmt=ilbm,bits=4,mode=gray,colors=4,dither=none,w=640,h=1024` (PAL and NTSC).
- Older firmware rejects type 4 at Open with `FN_ERR_INVALID`. The app maps
  that to "FujiNet firmware lacks image conversion" (`netmap_open_error`).
  Keep the open-stage and read-stage error mappings separate.
- xkcd JSON is filtered while it streams (`jsonstrip`), dropping `transcript`
  and `news`, so it fits a 4 KB buffer. A full buffer before EOF is a parse
  error, not a success.
- Changes needed in the firmware or the library belong in those repositories.
  Follow their AGENTS.md files and the workspace AGENTS.md section "Protocol
  changes span repositories": Python client, protocol docs, diagnostics on
  request, one function per lib file, and no committed UML diagrams.

## Verification

- Every change needs `make test` (ALL PASS) and `make amiga` (0 warnings).
- UI or behaviour changes also need a run in Amiberry. The workspace guide is
  `docs/amiga/amiberry-testing.md`; use `scripts/amiberry-ipc` for screenshots
  and input. Record what you checked, and say NOT RUN for anything you could not
  check. The last full acceptance record is `docs/acceptance-2026-10.md`.
- Never push without being asked.
